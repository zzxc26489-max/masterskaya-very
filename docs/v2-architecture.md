# Мастерская Веры V2 — архитектура

## Стратегия миграции

V2 живёт в `v2/` и использует существующие оптимизированные изображения. Старые HTML и CSS не изменяются. После утверждения дизайна страницы переносятся по одной, затем V2 становится корнем сайта.

## Первый вертикальный срез

```text
v2/
  index.html
  worlds.html
  residents.html
  birth.html
  assets/
    css/site.css
    js/site.js
```

В прототипе CSS находится в одном файле с `@layer`, чтобы визуальную систему было легко проверять. После утверждения файл разбивается без изменения каскада:

```text
src/v2/styles/
  tokens.css
  reset.css
  base.css
  layout.css
  components.css
  pages.css
  utilities.css
```

## Правила CSS

1. Mobile-first.
2. Один базовый блок на компонент.
3. Media queries меняют только необходимые свойства.
4. Никаких versioned append-only секций вида `v0.x fix`.
5. Никаких `!important`, кроме документированной утилиты доступности.
6. Все цвета, размеры контейнера, тени, радиусы, шрифты и интервалы идут через токены.
7. Компоненты не зависят от порядка страниц.
8. Page-specific селекторы не переопределяют базовый header, button или card.

## Правила JavaScript

- progressive enhancement;
- небольшие модули по функциям;
- отсутствие глобальных случайных эффектов;
- навигация остаётся обычными ссылками;
- JS не перехватывает все переходы между страницами;
- сохранение `aria-expanded`, Escape, возврата фокуса;
- фильтры и конструктор используют данные, а не генерируют структуру без fallback.

## Контент и данные

Следующий этап переносит Жителей из `assets/data/residents.js` в нейтральный JSON или ESM-модуль с валидируемой схемой:

```text
id
slug
name
collectionId
species
summary
origin
personality
story
availabilityStatus
availabilityLabel
images
constructorPreset
```

HTML-карточки должны создаваться во время build, а клиентский JS — только фильтровать уже существующую разметку. Это сохраняет SEO и работу без JavaScript.

## Изображения

- использовать WebP/AVIF с `srcset`;
- указывать `width` и `height`;
- hero получает `fetchpriority="high"`, остальные изображения — `loading="lazy"`;
- не использовать одну и ту же картинку в разных смысловых ролях без необходимости;
- будущие сгенерированные декоративные изображения должны иметь общий art direction и хранить prompt/source metadata в `docs/image-manifest.md`;
- изображения работ не заменять генерацией: генерация допустима только для фонов, орнаментов, карт и иллюстративных переходов.

## Конструктор V2

Конструктор не должен имитировать фабричную сборку. Его задача — подготовить направление заказа.

Шаги:

1. источник вдохновения или тип существа;
2. визуальный вариант;
3. взгляд, палитра и особые детали;
4. имя, краткое резюме и переход к обращению.

Предпросмотр использует одну основную фотографию/рендер и понятные акценты. Не накладывать текстовые заглушки поверх лица Жителя. Финальный результат формирует структурированное резюме и передаёт его на страницу контактов.

## Проверки

Минимальный CI для V2:

- `node --check v2/assets/js/site.js`;
- HTML link/resource audit только внутри `v2/`;
- CSS duplicate base selector audit;
- запрет подключения legacy CSS из V2;
- проверка пустых `href/src`;
- Playwright screenshots: 1440×1000, 768×1024, 390×844, 320×700;
- проверка отсутствия horizontal overflow;
- accessibility smoke test на меню, фильтры и формы.
