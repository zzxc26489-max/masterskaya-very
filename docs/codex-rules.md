# Обязательные правила для Codex

В начале каждой задачи Codex обязан:

1. Прочитать все документы в `docs/`.
2. Проанализировать текущую реализацию.
3. Перечислить файлы, которые собирается менять.
4. Не менять файлы, не относящиеся к задаче.
5. Создать отдельную ветку.
6. Не вносить изменения напрямую в `main`.
7. Не объединять pull request автоматически.

## Запреты

- Не переписывать проект на React, Vue или другой фреймворк без прямого указания.
- Не подключать внешние UI-фреймворки.
- Не удалять существующие изображения без прямого указания.
- Не менять терминологию проекта и названия навигации.
- Не создавать новые страницы без необходимости.
- Не добавлять случайные изображения из интернета.
- Не наслаивать новые CSS override поверх старых конфликтов, если можно исправить структуру.
- Не ломать GitHub Pages, поиск, формы или интерактивную логику.
- Не менять весь сайт в задаче об одной странице.
- Не использовать чрезмерные частицы, свечение или тяжёлые анимации.
- Не скрывать проблемы вместо исправления.
- Не заявлять о визуальной проверке, если браузер или скриншот-инструменты фактически не запускались.

## Обязательные проверки

После изменений выполнить: `git diff --check`; синтаксис изменённого JavaScript; локальные ссылки и изображения; при доступном браузере — отсутствие горизонтальной прокрутки, размеры 1440, 1024, 768, 390 и 320 px, клавиатурную навигацию, `prefers-reduced-motion` и отсутствие ошибок в консоли.

## Итоговый отчёт

Codex указывает, что изменено, какие файлы изменены, какие проверки выполнены, какие не удалось выполнить, что сознательно не менялось и какие риски остались.
